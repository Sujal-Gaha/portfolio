## What is the MVC Pattern?

Model-View-Controller (MVC) separates an application into three distinct responsibilities:

- **Model:** Manages the data schema, database queries, and business rules. In Node.js, models are typically built using libraries like Mongoose, Prisma, or Drizzle.
- **View:** Formats and presents data to the client. This can be server-rendered templates (EJS, Pug) or JSON payloads sent to a separate frontend client (React, Vue).
- **Controller:** Orchestrates requests. It accepts incoming HTTP requests, calls models to retrieve or mutate data, and sends the rendered view or response back to the client.

Separating these concerns prevents your route definitions from becoming massive files containing raw SQL, validation rules, and HTML generation all mixed together.

## Implementing MVC in Express

Express is intentionally unopinionated and does not enforce a specific directory structure. Here is a clean, practical way to organize an MVC project:

### 1. Project Directory Layout

```bash
my-express-app/
├── src/
│   ├── app.js               # Express application initialization and middleware
│   ├── server.js            # Port binding and startup
│   ├── models/
│   │   └── User.js          # Database schemas and data access
│   ├── views/
│   │   └── user.ejs         # Rendered templates (if using server-side views)
│   ├── controllers/
│   │   └── userController.js# Request handling logic
│   └── routes/
│       └── userRoutes.js    # Endpoint path definitions
├── package.json
└── .env
```

### 2. Setup

Install Express, Mongoose, and a template engine like EJS:

```bash
npm install express mongoose dotenv ejs
```

### 3. Code Implementation

Here is a minimal example fetching and rendering a list of users.

#### Model (`models/User.js`)

Defines the Mongoose schema:

```javascript
import mongoose from 'mongoose'

const UserSchema = new mongoose.Schema({
  name: { type: String, required: true },
  email: { type: String, required: true, unique: true },
  age: { type: Number, default: 0 },
})

export const User = mongoose.model('User', UserSchema)
```

#### View (`views/user.ejs`)

A server-side template to render the user list:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>Users</title>
  </head>
  <body>
    <h1>User Directory</h1>
    <ul>
      <% users.forEach(user => { %>
        <li><%= user.name %> (<%= user.email %>) - Age: <%= user.age %></li>
      <% }); %>
    </ul>
  </body>
</html>
```

#### Controller (`controllers/userController.js`)

Handles the request and coordinates between the model and view:

```javascript
import { User } from '../models/User.js'

export const getUsers = async (req, res, next) => {
  try {
    const users = await User.find().lean()
    res.render('user', { users })
  } catch (error) {
    next(error)
  }
}
```

#### Routes (`routes/userRoutes.js`)

Maps HTTP endpoints to controller actions:

```javascript
import express from 'express'
import { getUsers } from '../controllers/userController.js'

const router = express.Router()

router.get('/users', getUsers)

export default router
```

#### Application Entry Point (`app.js`)

Connects database, configures view engine, and attaches route handlers:

```javascript
import path from 'path'
import { fileURLToPath } from 'url'
import express from 'express'
import mongoose from 'mongoose'
import userRoutes from './routes/userRoutes.js'

const __dirname = path.dirname(fileURLToPath(import.meta.url))
const app = express()

// Connect to MongoDB
mongoose
  .connect(process.env.MONGO_URI || 'mongodb://localhost:27017/mydb')
  .then(() => console.log('MongoDB connected'))
  .catch((err) => console.error('MongoDB connection error:', err))

// View engine configuration
app.set('view engine', 'ejs')
app.set('views', path.join(__dirname, 'views'))

// Middleware and routes
app.use(express.json())
app.use(express.urlencoded({ extended: true }))
app.use('/', userRoutes)

app.listen(3000, () => {
  console.log('Server running on http://localhost:3000')
})
```

## When to Use MVC (and When to Move Beyond It)

- **Good fit for server-rendered or mid-sized REST APIs:** Grouping routes, controllers, and models gives you a predictable place for every piece of code.
- **For APIs with complex business rules:** Consider adding a `services/` layer between controllers and models. Keeping controllers responsible only for HTTP concerns (status codes, headers, parameter extraction) while delegating business logic to service functions makes testing and reuse much easier.
