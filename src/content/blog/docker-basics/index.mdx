Docker packages applications and their dependencies into portable, isolated containers. Unlike traditional virtual machines that require a complete guest operating system, containers share the host Linux kernel. This makes them fast to boot, light on resource usage, and predictable between local development and production servers.

To follow along, make sure Docker is installed on your machine ([docker.com](https://www.docker.com/)) and confirm it runs in your terminal:

```bash
docker --version
```

---

## 1. Docker Images

An image is an immutable, read-only blueprint used to instantiate containers. It packages your code, runtime, system tools, and libraries.

- **Base Images:** Most images build on top of an official distribution or runtime, such as `alpine`, `ubuntu`, or `node:20-alpine`.
- **Layers:** Each instruction in a build creates an immutable layer. Unchanged layers are cached, which speeds up subsequent builds.
- **Tags:** Versions appended to image names, such as `nginx:alpine` or `node:20.10-slim`. Omission defaults to `:latest`.
- **Registries:** Central storage for images, including Docker Hub and private registries like AWS ECR or GitHub Container Registry (GHCR).

### Essential Image Commands

```bash
# Search for an image on Docker Hub
docker search nginx

# Download an image locally
docker pull nginx:alpine

# List locally downloaded images
docker image ls

# Build an image from a Dockerfile in the current directory
docker build -t my-app:1.0.0 .

# Tag an existing image for a remote repository
docker tag my-app:1.0.0 myusername/my-app:1.0.0

# Push an image to a registry
docker push myusername/my-app:1.0.0

# Delete a local image
docker image rm my-app:1.0.0
```

## 2. Docker Containers

A container is a live, running instance of an image. It runs as an isolated process on the host system with its own filesystem, network stack, and process tree.

### Running and Managing Containers

```bash
# Run a container in detached mode (-d) and map host port 8080 to container port 80
docker run -d -p 8080:80 --name web-server nginx:alpine

# View actively running containers
docker ps

# View all containers, including stopped ones
docker ps -a

# Stop and restart a running container
docker stop web-server
docker start web-server

# View container output logs (-f follows live stream)
docker logs -f web-server

# Open an interactive shell inside a running container
docker exec -it web-server sh

# Remove a stopped container
docker rm web-server
```

## 3. The Dockerfile

A Dockerfile contains step-by-step instructions for building a custom container image.

### Typical Node.js Dockerfile Example

```dockerfile
# Use an explicit LTS runtime rather than generic latest
FROM node:20-alpine

# Set working directory inside the container
WORKDIR /app

# Copy dependency definitions first to leverage layer caching
COPY package*.json ./
RUN npm ci --only=production

# Copy application source code
COPY . .

# Expose port documentation
EXPOSE 3000

# Start command
CMD ["node", "src/index.js"]
```

### Build Tips

- Always add a `.dockerignore` file containing `node_modules`, `.git`, and environment files so you do not copy local bloat into the image.
- Order steps from least frequently changed (installing OS packages, downloading dependencies) to most frequently changed (copying app source) so Docker reuses cached layers.
- For compiled languages like Go or Rust, use multi-stage builds to compile in a heavy builder stage and copy only the final binary into a minimal scratch or alpine image.

## 4. Volumes and Persistent Storage

By default, the filesystem inside a container is ephemeral: when the container is removed, any data written to its local filesystem is lost. Volumes solve this by mounting directories from the host.

- **Named Volumes:** Docker manages storage inside `/var/lib/docker/volumes/`. Best for databases and state that needs to survive container recreation.
- **Bind Mounts:** Maps an explicit host path (like your local source folder) into the container. Common in development for live reloading.

```bash
# Create a managed volume
docker volume create postgres_data

# Run Postgres using the managed volume for its database storage
docker run -d \
  -p 5432:5432 \
  --name local-db \
  -e POSTGRES_PASSWORD=secret \
  -v postgres_data:/var/lib/postgresql/data \
  postgres:16-alpine

# Mount your current project folder for local development
docker run -d -p 3000:3000 -v $(pwd):/app --name dev-app node:20-alpine

# List and clean up unused volumes
docker volume ls
docker volume prune
```

## 5. Container Networking

Docker assigns containers their own internal IP addresses. To let multiple containers talk to each other by name, place them on a user-defined bridge network.

```bash
# Create a dedicated network for an application stack
docker network create app-network

# Run a database attached to the network
docker run -d --network app-network --name database postgres:16-alpine

# Run an API attached to the same network; it can reach the database using 'database:5432'
docker run -d --network app-network -p 3000:3000 --name api my-api:latest

# Clean up networks
docker network ls
docker network rm app-network
```

## 6. Docker Compose

When an application relies on multiple containers (such as an API, a database, and a cache), typing separate `docker run` commands becomes tedious. Docker Compose lets you define the entire stack in a single `docker-compose.yml` file.

```yaml
version: '3.8'

services:
  api:
    build: .
    ports:
      - '3000:3000'
    environment:
      - DATABASE_URL=postgresql://postgres:secret@db:5432/mydb
    depends_on:
      - db

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: mydb
    volumes:
      - db_data:/var/lib/postgresql/data
    ports:
      - '5432:5432'

volumes:
  db_data:
```

### Running Compose

```bash
# Start all services in the background
docker compose up -d

# Check status of compose services
docker compose ps

# View aggregate log output
docker compose logs -f

# Shut down all services and remove their network
docker compose down

# Shut down and remove persistent volumes as well
docker compose down -v
```

## 7. Registries and Publishing

Once you build and tag your image, you can push it to Docker Hub or any OCI-compliant registry:

```bash
# Authenticate with Docker Hub
docker login

# Tag the image with your Docker Hub handle
docker tag my-app:latest username/my-app:1.0.0

# Push the image
docker push username/my-app:1.0.0

# Log out when finished
docker logout
```

These core primitives (images, containers, volumes, networks, and compose) form the baseline for building and running containerized services locally and in deployment pipelines.
